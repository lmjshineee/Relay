# 第一批：看清 agent 的工具调用循环

这一批的目标是让你能解释一次工具调用如何发生，并能改动其中一个环节。我们先把模型替换成固定脚本，让 Python 部分的行为可预测。它是 agent 循环的练习支架，还不能自主判断或修复代码。

### 1. 先运行，预测输出

在 Relay 根目录执行：

```bash
python3 -m relay demo
python3 -m unittest discover -s tests -v
```

第一次运行前先猜：读两次文件、结束一次，`model_calls` 应该是多少？答案是 3。工具执行不是模型生成；每次 `generate` 交出一个动作，这个演示共交出三个动作，真实 API 请求为零。

输出包含 `messages` 和 `events`。前者是下次模型请求会收到的对话，后者便于查看执行过程。当前都只在内存中收集，程序崩溃后不会自动恢复。需要保留时可用 shell 重定向保存：

```bash
mkdir -p .relay
python3 -m relay demo > .relay/demo.json
```

`completed` 是对话结束；`verification: not_run` 是没有独立验收。这两个概念要从第一天分开。示例中的错误公式故意保留，不能用这个演示声称已经修好平均数函数。

### 2. 按这三个文件理解职责

1. [`tools.py`](../relay/tools.py)：真正访问文件系统。`READ_FILE_TOOL` 描述工具参数，`execute_tool` 在运行时检查参数和路径。描述告诉模型如何请求；Python 检查决定请求是否能执行。只提供 schema 不会自动产生权限限制。
2. [`models.py`](../relay/models.py)：定义 `generate(messages, tools)` 边界。`ScriptedModel` 只是依次返回预写字典，甚至不会读取传入的对话；它不能证明真实模型会选择工具、理解文件或修正错误。之后真实适配器要把内部消息和工具 schema 转成所选提供商的格式。
3. [`loop.py`](../relay/loop.py)：保存对话，请求模型，检查响应类型，分发工具，再把观察追加到对话中。它决定是否继续以及何时停止。`__main__.py` 只负责解析命令行和输出 JSON。

一轮具体过程是：`generate` 返回 `read_file` 请求 → Python 检查并读取文件 → 添加 `role: tool` 消息 → 下一轮把更新后的 `messages` 传给模型。请求与结果通过 `tool_call_id` 对应。模型看见工具结果后，才有信息决定下一步。

当前内部响应只有两种：

```json
{"type": "tool_call", "name": "read_file", "arguments": {"path": "issue.md"}}
{"type": "finish", "content": "我的回答"}
```

这些是 Relay 教学协议，不是任意模型 API 可以直接接受的请求体。每轮只允许一个工具请求，方便你从头追踪。一次读取最多 200 行，后续可用 `start_line` 接着读；超过 64 KiB 的文件直接返回错误。

### 3. 做四个小实验

每次按“先预测 → 改动或运行 → 看 JSON → 解释原因”的顺序，不急着增加工具数量。

1. **观察信息流。** 找到 `call-1` 的请求和结果，解释 `role: assistant` 为什么不能代替 `role: tool`。再读 `test_next_model_request_sees_matching_tool_result`：它用测试模型根据实际读取结果生成回答，验证观察确实传进了下一轮。
2. **制造缺失文件。** 把 `demo_model()` 第一次请求的路径临时改成 `missing.md`。预期工具结果是 `not_found`，循环仍可继续，但预写结论不会改变。解释为什么这证明了脚本模型的局限。实验后恢复路径。
3. **触及权限边界。** 把第一次路径改成 `../README.md`。预期得到 `outside_workspace`，文件内容不会返回。即使这个文件真实存在也一样，因为工具范围由传入的工作区决定。实验后恢复路径。
4. **让循环提前停止。** 运行下面的命令，预期 `status: step_limit`、`model_calls: 1`、`answer: null`，退出码为 1。解释为什么不能把已经读完一个文件当作任务完成。

```bash
python3 -m relay demo --max-steps 1
```

再运行测试确认恢复了示例。测试文件同时可以当作失败行为的可运行说明：缺失文件、错误参数、未知工具、路径越界、外部符号链接、输出限制、模型异常、错误响应和命令退出码都有例子。

### 4. 这一批的验收与边界

2026-10-23 在 Python 3.14.9 上运行 17 项测试，全部通过；离线演示完成三轮脚本响应、两次文件读取。测试检查 fixture 字节未变化，以及下一次模型请求能收到匹配的工具结果。这是代码行为检查，不代表你已经掌握这些知识。

读完后尝试不用代码回答：模型提出了什么？Python 执行了什么？工具错误如何返回？步数上限由谁控制？对话结束和修复成功有什么区别？能用自己的话说明这五件事，比背一个框架 API 更有用。

本切片只针对静态本地 fixture。普通路径校验不是容器或操作系统权限隔离；它不处理其他进程同时替换路径的竞态。没有恢复协议、成本账本、真实提供商、写文件、运行命令或代码修复验收，也没有完成完整开发计划中的 T01。
