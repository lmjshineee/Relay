# Relay 设计依据与待定决策

初始日期：2026-10-18；教学切片决策更新于 2026-10-23。本文区分需求、设计建议、实现决策和外部资料。

### 1. 需求来源

项目起点是关于 Coding Agent Harness 的私人设计讨论，原始对话不作为公开仓库的阅读前提。以下保留自包含的需求与设计背景。

初始需求：设计一个有明确系统问题、可扩展、可展示并能为后续 Infra 学习提供基础的 coding agent harness，形成开发方案、指南和规范。实施阶段新增学习目标：从小批量、能运行的代码开始理解 agent。

参考回复建议了 Relay 名称、故障恢复主线、上下文策略、Python/SQLite/Docker 技术路线、固定任务集、消融实验和后续推理服务扩展。这些内容构成本轮设计起点；其中引用标记无法直接还原成可访问来源，因此未将原回复的全部研究论断作为已验证事实复制。

历史状态：2026-10-18 创建初始设计文档时，工作区为空，尚无实现。2026-10-23 已完成前置教学切片，范围见本文 D11 与 [实现进度](08-project-status.md)；尚未调用收费模型或运行正式评测。

### 2. 默认设计决策

| ID | 决策 | 理由与代价 | 何时重审 |
|---|---|---|---|
| D01 | 单机单 agent，单 run 顺序动作 | 缩小恢复状态空间；暂不能测多任务吞吐 | 正确性门槛完成且有并发需求 |
| D02 | Python + 类型化模型 | 快速实现与测试；运行时开销需实测 | profiling 显示控制面瓶颈 |
| D03 | 宿主 SQLite 单写，Worker 写 spool | 独立 Worker 能跨 Controller 存活；增加回执导入协议 | 多机器或高并发写入 |
| D04 | 专用单文件替换 + 受限 shell | 可核对修改与灵活工具并存；shell 恢复较保守 | 有证据支持更丰富幂等工具 |
| D05 | UNKNOWN shell 默认阻塞 | 不把无法确认的副作用当可重试 | 任务明确支持完整快照与自动回滚 |
| D06 | 内容寻址快照，静止边界创建 | 覆盖未跟踪文件；存储与静止检测有成本 | 实测快照成为瓶颈 |
| D07 | 预算预留与未知用量并存 | 响应丢失时仍保守控制费用；可能过早停机 | 提供商支持可靠账单对账 |
| D08 | 独立隐藏验收，一次最终评测 | 降低评分器污染与反馈泄露 | 另设计明确的迭代评测协议 |
| D09 | 事件永久保留于本次实验存储期 | 支持追溯与重新构建上下文；占用磁盘 | 引入有明确保留周期的归档与清理 |
| D10 | 自建小型恢复内核，参考外部框架 | 主亮点可解释、可实验；承担实现成本 | 项目目标转向应用交付速度 |

“永久保留”在本项目语境中表示运行与实验期间不因压缩或回滚删除原始事件，并非承诺无限磁盘容量。清理由显式归档策略管理，不能破坏仍被引用的报告证据。

### 4. 本轮核对的官方资料

1. [mini-swe-agent 仓库](https://github.com/SWE-agent/mini-swe-agent)：参考小型 agent 循环与环境边界。Relay 不复制其宣传分数为自己的指标，也不把“核心约百行”当整个系统工作量。
2. [LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)：说明 checkpoint 与持久存储的职责。原 durable-execution 链接在本轮访问时重定向到此页；本文的动作对账协议是 Relay 的设计建议，不能视为该页提供的 exactly-once 保证。
3. [SQLite Write-Ahead Logging](https://www.sqlite.org/wal.html)：用于核对 WAL 的并发与持久化边界。Relay 采用单写者和短事务；WAL 不替代跨文件、跨进程副作用协议。
4. [vLLM Automatic Prefix Caching](https://docs.vllm.ai/en/latest/features/automatic_prefix_caching/)：用于限定前缀缓存的收益解释，重点是 prefill；实际效果受工作负载影响。

上述资料于 2026-10-18 访问。实现时应锁定实际使用的版本与必要的文档链接。本文不依赖在线库最新版本号，也未声称这些组件已在本机兼容验证。

### 5. 未验证假设与需要实验的结论

恢复机制是否减少任务总费用，取决于故障频率、checkpoint 成本和可恢复范围；上下文压缩是否降低费用，取决于摘要开销、缓存行为与成功率；某套固定任务集能否反映真实工作，需要任务分布和失败案例支撑。

预期亮点应表述为待检验问题。阶段报告必须允许出现“效果不明显”“成本增加”“只在特定故障下有效”的结果，并解释原因。

### 7. D11：先实现学习用工具调用循环

状态：accepted。日期：2026-10-23。适用于第一批教学代码。

用户希望先写一批，以学习 agent 为主要目标。因此在正式 T01 前增加前置教学切片：Python 标准库、一个只读工具、一个脚本模型、同步单循环和 unittest。使用扁平 `relay/` 包，直接通过 `python3 -m relay demo` 运行；当前 Python 3.14.9 已实测，声明支持 Python 3.11+，其他版本尚未实测。

本切片没有第三方运行依赖，因此暂不引入 SDK、uv 锁文件、Docker、SQLite、异步或写入工具。JSON 轨迹是内存记录的导出，不是持久事件库；`call-1` 等 ID 只在本次调用内关联消息，不具备恢复、去重或跨运行身份语义。工具路径检查用于静态本地 fixture，不提供恶意进程并发修改路径时的沙箱隔离。该切片不满足完整 runtime 的持久化和独立验收发布门槛，不把 `completed` 映射成 `SUCCEEDED`。

下一步接入一个真实模型适配器，检验模型是否能根据工具观察调整后续动作；选择提供商和费用上限后再引入对应依赖和锁文件。新增写入或执行工具前重审隔离、持久意图和独立验收契约。
